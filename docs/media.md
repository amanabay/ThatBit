# Media, clocks, and capture decision

Engineering experiment: FFmpeg 8.1.3 generated a numbered 12-second VP9/Opus fixture. Integration tests ingest a real generated 4-second recording, retain it across a SQLite close/reopen, render [1,3), probe two-second output, and render/probe portrait with approved captions. This verifies real media processing; it does not verify microphone capture, OBS mute behavior or audible human speech.

Decision: implement a narrow browser screen/tab capture and finalized OBS import first. Browser selection exposes exactly what the user chose and requires a shared audio track. OBS split ingestion is now implemented with a separately configured authenticated local OBS instance; its protocol fixture does not replace actual device acceptance. Device permission, audio-route availability and A/V sync are pending human checks. Supported tested media is WebM VP9/Opus; MP4/MKV support depends on local decoders. Fedora's FFmpeg may lack H.264 decoding; import a WebM recording if probe/decode fails.

Browser capture uses MediaRecorder with roughly 1.5-second data events, but does not assume timeslice timing is exact. Each chunk has an immutable sequence/hash, browser elapsed time, BlobEvent timecode and server receive timestamp. Chunks are flushed and promoted before their metadata/acknowledgment commits. Retries use the same sequence and bytes; changed retries or missing sequences fail. The upload backlog is capped at 16 MB and individual chunks at 8 MB. Backpressure/device loss ends the epoch rather than silently bridging a gap. MediaRecorder's data events are not individually playable files: the adapter joins bytes from one epoch and FFmpeg remuxes them into a finalized owned asset.

One epoch permits one hour / 220 MB, with at most 512 MB of unresolved chunk data across captures and five interrupted epochs. Finalized source storage remains 200 files / 5 GB. Browser captures do not automatically rotate or evict unfinished epochs; managed OBS segments have separate rolling retention described below. The beginning of a long exchange is retained because all acknowledged chunks remain protected until finalization/discard. A live “Save that exchange” snapshot owns its complete acknowledged source; its default last-30-second suggestion is a manual starting point and can be expanded (approved intervals remain ≤180 seconds). Snapshots reuse stable operation keys after interrupted linkage rather than silently selecting a different source.

On reload/restart, the epoch becomes recoverable/interrupted and its unacknowledged tail is explicitly unknown. Recovery never claims to reconstruct unreceived data. A finalized media asset is validated before the session references it. Finished/discarded raw chunk files may then be removed; immutable sources used by drafts are separate and remain protected. Backups include acknowledged chunks for pending epochs and verify their hashes. Orphan/temp files from an OS kill still require maintenance; graceful error paths clean their scratch files.

Time conventions: chat receivedAt remains a Twitch envelope time or manual creation time. Capture clientWallAt and clientMonotonicMs anchor the client setup request; browser elapsed/timecode values are recorded independently from server arrival. These do not prove when a spoken response reached the broadcast. Finalized-media presentation timestamps remain authoritative for trims. Each capture is a separate epoch; no interpolation across restarts, pauses or source changes. Media intervals are half-open [start,end); captions are seconds relative to that interval, ordered and contained. Audio/video synchronization and broadcast-delay calibration require real capture acceptance.

Rendering decodes/re-encodes into a separate WebM. The source is never served as a public file with client-side seek bounds. Private lead-in preview does not extend publication. Portrait uses only approved derived media, original message and approved captions. Full source frame is fitted into 720×1280 rather than cropped. Message limit for portrait is 400 characters; longer context remains in the replay page. Word timing, variable-frame-rate edge cases, exact human syllable boundaries and real audio sync require further tests.

Local transcription: install/build [whisper.cpp](https://github.com/ggml-org/whisper.cpp), select a model, set WHISPER_BIN and WHISPER_MODEL to absolute server-side paths. UI queues analysis of the exact saved interval (at most 180 seconds), even late in a long file, with two CPU threads and a five-minute inference timeout. FFmpeg extracts only that interval; provider millisecond offsets are converted into source-media seconds. Jobs have persisted attempt counts, an eight-minute lease marker and generation fencing; startup recovers abandoned work under the exclusive process owner. One job runs at a time, queue capacity ten, maximum three automatic attempts with backoff. Cancellation signals local subprocesses and fences late results. Invalid timings/output fail privately rather than becoming captions. Completed transcripts retain source revision, interval, provider/model label and validation provenance. Results cannot be silently applied to a different revision. JSON offsets are validated and divided from milliseconds into seconds. No fabricated word timing. No audio leaves this machine, no API charges. Pinned model installation and prerecorded-speech inference have passed locally; creator speech accuracy and live latency remain unverified. Caption corrections create a new draft revision; original transcript is retained with source revision provenance.

Preserve `.data/media` with the database. Referenced immutable sources are retained; only unreferenced managed OBS segments have automatic retention. Missing/corrupt files fail processing or playback; choose another source or restore a verified backup. Crash-orphan files may be retained for inspection; stop app before manual cleanup. Hardware impact, 60-minute memory bounds, disk-full injection and real mute/device-loss scenarios are pending.

Official capture references checked for this slice: [MediaRecorder data events](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event), [BlobEvent timecode](https://developer.mozilla.org/en-US/docs/Web/API/BlobEvent/timecode). Browser tests exercise actual MediaRecorder output from a labelled generated canvas and sine tone. Provider tests use a fixture CLI, not a speech model. Neither is a live-device or real-ASR acceptance claim.

## OBS ingestion and assistance

On Fedora, keep the OBS application running while ReplyLink connects. Enabling its WebSocket setting on disk does not start a server when OBS is closed. Check `ss -ltnp 'sport = :4455'`: a listener must exist on the configured port. An initial failed connection now reports “OBS unreachable” with an action to open OBS; it does not claim that a recording gap occurred. ReplyLink retries automatically. Authentication failures remain a separate status. Native and Flatpak OBS can use different configuration directories; verify the running installation before copying settings.

OBS support now authenticates on loopback, checks SplitRecordFile capability, listens for recording file transitions and imports closed segments every 30 seconds. Start ReplyLink before starting OBS recording, and use a split-capable MKV profile. OBS start events have a null outputPath; the first path is known only at a split, and its closed segment arrives at the next split (normally about 60 seconds). The initial file remains in the original recording. OBS_AUDIO_TRACK selects recorded audio track 1–6 (default 1); verify it is the intended OBS mix. Scratch files live in managed local storage, not in the original recording directory. Originals are never deleted. Unreferenced owned segments age out after 15 minutes; immutable draft revisions and pending analysis protect their sources.

Automatic candidates are generated only when local Whisper and the semantic model are configured. Matching uses real local quantized embeddings with an experimental threshold and ranking margin; no calibrated confidence is claimed. Candidate captions/excerpts must match supplied source segments and remain private. Automatic candidates currently cover one closed segment. Save OBS exchange can preserve multiple contiguous closed segments in an independent source: up to six segments, 180 seconds and 220 MB; UI presets select up to 150 seconds. Gaps, pauses and reconnects create separate epochs or discontinuous segments and cannot be silently joined. Active assemblies pin their inputs; saved snapshots survive expiry of their input segments. In-progress OBS tails are not included. Use the original recording for longer or incomplete answers. Track selection is local environment configuration; real OBS mute/pause/sync rehearsal remains pending.

OBS normalization has a four-file backlog; overload retains originals and reports a manual recovery action. Automatic analysis permits ten queued jobs, three attempts and bounded backoff. Failed/skipped jobs do not retain unreferenced media forever. The semantic model uses two intra-op threads and one inter-op thread. Explicit deferrals/missing speech abstain; this heuristic can also miss valid nuanced answers. Source clock calibration, cross-segment automatic suggestions and resource impact require rehearsal.

Local transcription boundary correction: Whisper can place a final sentence end in model padding beyond the supplied WAV (observed 31.04 seconds for a requested 30-second selection). The Whisper adapter now probes the extracted WAV and intersects estimated sentence times with the actual audio/requested interval; wholly padded segments are omitted. General provider ordering/interval validation remains strict. Captions still require listening/review; bounded sentence estimates are not word-level precision. The original recording and the selected published interval are not expanded.
