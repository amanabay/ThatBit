# Local operation; future Render deployment

No hosting is required. No Render service has been created and no Render credit is used.

Run `npm run build` once, then `npm run dev:local`. Creator remains on http://localhost:4317 and a separate managed reader runs on http://localhost:4320. A random writer capability is shared only in child-process environment; it is not printed or committed. Persistent reader data lives in `.data/reader`. Approve/render locally, then choose **Publish to reader**. The reader stages the immutable manifest, verifies uploaded bytes and media duration, then commits availability. **Open reader replay** opens that independent copy. Unpublish/source removal queues reader withdrawal, confirmed separately; failed synchronization has an explicit retry action. Keep both processes running until removal is acknowledged.

A reader restart retains committed availability and withdrawal tombstones. Older uploads cannot reactivate a withdrawn generation. Staged/failed uploads are not public. The legacy `export:public` command still creates static snapshots; it does not offer automatic revocation and is not the managed workflow.

The managed reader generates a 1200 × 630 PNG from the approved derived replay before acknowledging availability. Replay HTML includes Open Graph/Twitter card metadata without needing client JavaScript. `READER_PUBLIC_ORIGIN` sets absolute preview/canonical URLs; only HTTPS or loopback HTTP is accepted, and request Host/forwarded headers never supply it. The default is localhost at the reader port; on Render, the provided `RENDER_EXTERNAL_URL` is used automatically unless explicitly overridden. An existing available reply without a PNG generates one on its first preview request, with one generation at a time. Removal gates both HTML metadata and the image, and cleans the managed PNG. External platforms can retain cached previews or downloaded copies; removal cannot recall them. Static exports and creator-only replay URLs do not supply these managed-reader previews.

Optional local container: `READER_WRITE_TOKEN=<local-random-token> docker compose up --build`. Set the same token and READER_URL=http://127.0.0.1:4320 in the creator configuration, and start the creator separately. Compose binds only loopback and uses a named persistent volume. Do not run Compose and dev:local on the same reader port. Container builds download software packages, never your recordings.

## Render preparation only

`deploy/render.yaml` describes a future Docker web service, explicit paid compute, 10 GB persistent disk at /var/data, health check and disabled automatic deploys. Render free ephemeral storage is not durable SQLite/media storage. Importing the Blueprint would provision a paid service; do not import it until separately authorized. A purchased domain is unnecessary; Render provides a service hostname and TLS.

`.github/workflows/deploy-render.yml` is manual-only, requires the DEPLOY confirmation, a render-production environment and a secret deploy hook. Configure environment protection/review in GitHub before enabling it. No hook/credentials are included. Ordinary checks never invoke Render. The hook response only starts a deployment; verify Render completion, /healthz, range playback, captions, restart persistence and removal before enabling external sharing. Configure READER_URL/READER_WRITE_TOKEN locally afterward; remote writer transport requires HTTPS.

Only approved derived video and metadata go to a future host. Raw recordings, drafts, OBS/Twitch secrets and local AI stay on the creator machine. The writer API is a scoped publishing capability, not creator administration. Back up reader SQLite together with reader media. Rollback code must preserve tombstones and never restore an old available generation over a later withdrawal. To remove managed access immediately, stop the reader; downloaded copies and already-open streams cannot be recalled.

The manual workflow runs the full local gates and a Docker restart/publishing smoke before requesting the exact checked Git commit with the hook's `ref` parameter. It serializes deployment requests and never runs on ordinary pushes. Hook success means requested/queued, not deployed. See the official [deploy hook](https://render.com/docs/deploy-hooks), [persistent disk](https://render.com/docs/disks) and [Blueprint](https://render.com/docs/blueprint-spec) documentation. Actual container/Render and external-network acceptance are recorded separately in testing.md.
