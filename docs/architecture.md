# Architecture and decisions

Application diagnostics use an injected port with a quiet default; domain rules remain deterministic and free of I/O. Production entrypoints supply a local adapter that allowlists metadata and classifies errors without serializing messages, headers, payloads or subprocess output. Fastify hooks use registered route templates and generated request IDs; AsyncLocalStorage links awaited application events to the current request. Background work uses persisted job/publication IDs, independently of HTTP lifetime. The adapter writes readable CLI events and bounded private JSONL files; file errors disable that file sink while leaving CLI and application work running. Fatal startup/uncaught/rejected failures exit after a sanitized event. Fastify request-ID/header behavior was checked against its [official logging reference](https://fastify.dev/docs/latest/Reference/Logging/). Operation is documented in logging.md.

2026-10-29: TypeScript/ESM modular monolith, Node 24 and React/Vite. Dependencies checked against official Vite guide; Vite 8.3.5 installed with lockfile. SQLite uses Node's built-in binding to avoid a native dependency; this binding emits an experimental warning on this runtime. FFmpeg is a managed subprocess with explicit arguments, two encoding threads and a timeout.

Domain holds interval/version/removal guards and conservative matching. Application services own approval, revision creation, rendering orchestration and intelligence. Adapters own SQLite, media tools, Twitch and local transcription. HTTP parses and authenticates, then invokes services. Browser code uses Zod contracts and never imports server code. `check:boundaries` checks imports and negative fixtures. It is a focused regex policy, not a complete TypeScript graph proof.

SQLite migration v1: a keyed `(kind,id,json)` records table, schema-validated at reads, plus an owner table. Kind separates immutable revisions, messages, finalized assets, approvals, publication/jobs, deliveries and transcripts. This deliberately avoids a package per entity. JSON storage is simple but incurs full scans; not suitable for a large collection. A future v2 must transactionally migrate rows with an explicit user_version guard and fixture-backed upgrade test. Do not silently change stored field semantics.

`BEGIN IMMEDIATE` makes revision compare-and-write and approval+queued work atomic. Latest draft edits create new revision rows; publications reference exact revision IDs. Publication records double as bounded durable render jobs. States: queued → rendering → published, or bounded retry → failed; removal increments generation and prevents stale worker completion. Rendering restarts are recovered to queued under a single process owner. One worker, ten queued operations, three render attempts with delay. Source-message removal invalidates related publications transactionally.

SQLite cannot commit media files. Ingest writes and flushes a temp file, probes it, renames it, syncs its directory, then commits metadata. A crash before metadata commit may leave an orphan; no automatic deletion currently runs. Saved metadata cannot make a browser's unfinalized buffer durable. Sources are immutable, hashed and retained. OBS retention checks revision references, queued analysis and active assembly pins transactionally before marking a source for deletion. New draft saves reject deleting sources. Immutable referenced assets remain protected.

The local capability is generated at startup and bootstrapped only from the same origin. Mutations require the header token; private media can use a same-site HttpOnly cookie. Origin/Host checks reject hostile browser requests. This protects against hostile web origins, not malware or another trusted process on the creator's OS account. All creator routes remain loopback-only.

Public projections contain message, author, creator, approved title/date/duration/captions, fixture label and publication ID only. Public video/caption/export routes re-check availability for each request. The managed reader owns a separate SQLite database and derived media only, without creator routes, raw sources or Twitch/OBS integration credentials. Writer authentication authorizes the narrow management API. The legacy static-snapshot reader instead reads an exported manifest. Downloaded bytes and already-open streams cannot be recalled. Public caching is disabled.

Capture epochs and durable transcription jobs are now explicit persisted record kinds. Capture byte chunks are private; snapshot assets are finalized through the same ingestion port. Analysis jobs target immutable source revisions, persist attempt/lease/generation state, and atomically commit validated transcript results and completion. No general workflow engine is introduced. The exclusive owner reclaims interrupted jobs on startup; this is not a multi-host lease system. Managed reader synchronization and OBS rolling retention are implemented; external deployment acceptance and broadcast-delay calibration remain open. Full resource/fault-recovery claims await rehearsal.

Second-slice storage is additive: new capture, capture-chunk, asset-operation and analysis-job record kinds do not change the v1 physical schema. Previous source/revision/publication records are preserved. Legacy unqueued transcript records remain private and are not reinterpreted as new revision-bound job output.

Managed publishing uses persisted synchronization jobs and exact publication generations. Reader staging verifies size, SHA-256 and probed duration before availability. Withdrawal tombstones commit before file cleanup, fence stale uploads and survive restart. Both creator and managed reader hold a lifetime SQLite exclusive transaction on a separate owner-lock file. The OS releases it on exit/crash, without relying on PID liveness across container restarts. Reader startup reconciles leftover temporary/withdrawn files; disk quota is 5 GB of active/staged manifests. HttpPublisher rejects redirects and requires HTTPS except on loopback.

OBS uses epoch/sequence metadata for contiguous assembly. Assembly pins are persisted before asynchronous media I/O and cleared during exclusive-owner recovery. A crash can leave scratch copies, but cannot cause retention to report an unsaved draft as saved. Automatic assistance validates provider timing and matcher evidence against actual supplied captions; it has no approval, publication or chat-send port. No schema migration is required: OBS segments, assembly pins, auto-jobs and synchronization are additive record kinds with explicit legacy continuity defaults.

The previous PID/nonce ownership table is no longer used by the owner adapter; existing rows remain inert. Stop any older app version before upgrading. The new owner-lock file is coordination metadata, not collection data and not part of backups. Container restart testing prompted removal of the PID 1 reuse assumption; the OS-backed lock and a cross-process SIGKILL regression replace that unsafe assumption.

Managed reader previews are derived only from the immutable approved PublicReply and its already-trimmed WebM. FFmpeg uses bundled fonts, literal text files with drawtext expansion disabled, a bounded single-frame process and private temporary scratch files. Upload availability waits for the flushed PNG, with the same generation check as video. Removal commits its tombstone before pruning both formats. Legacy available records generate missing previews lazily with bounded concurrency and a final availability check. Reader HTML loads its shell before the synchronous availability lookup and escapes approved text into metadata. Absolute links use validated configuration rather than request headers. No new database schema or creator/private data access is needed.

The creator read model now projects publication content from the immutable referenced revision, independently of the latest draft. Structured OBS health stays private; a separate authenticated inspection strips names/settings to safe source kinds and mute/routing flags. Creator polling has a bounded timeout and a visible stale state. Private review notes are append-only assessments of saved revisions, with authenticated export and no publication authority.

Automatic analysis captures an epoch/sequence-bounded source window at queue time. All source IDs and any prepared assembly are retained while pending; prepared asset identity survives retries/restarts. Unused analysis-source copies join the same transactional deletion/pinning policy as rolling segments. Immutable revisions protect independent joined media. Provider/model labels pin new analysis jobs; known configuration changes fail explicitly. Suggestions deduplicate original messages across overlapping windows, including discarded suggestions. The composition root reuses one bounded local semantic model until shutdown. Physical SQLite schema remains v1; new provenance, analysis-source, review-note and chat-clear kinds are additive.

Chat clears use explicit source-event timestamps and preserve nanosecond ordering for cutoff comparisons; no ambient clock estimates message order. Source-scoped individual deletion and room/user fences exclude manually entered/fixture data and fence publication generations. Per-socket watchdogs keep reconnect handoff from cancelling another connection’s health checks. Auth validation failure and revocation terminate intake without automatic send/retry. Envelope dedupe/fragments and broader lifecycle faults remain documented limits.

Operations uses a resource-measurement port; the adapter samples process RSS/CPU, instance identity and free disk while the application projects only quota/queue/failure counts. The authenticated DTO contains no chat, transcripts, paths or credentials. The loopback-only rehearsal CLI validates that DTO before writing private no-overwrite JSONL/summary artifacts. CPU comparisons skip process-instance changes. Resource observations explicitly exclude reader/OBS/subprocess resources and human acceptance.


2026-10-31: SQLite schema v2 adds expression indexes for source-message identity and latest draft revisions, without rewriting stored records. Newer unknown schemas are rejected. Nested transactions use savepoints; rollback respects SQLite's automatic transaction abort on `SQLITE_FULL`. Creator inbox uses rowid cursor pages with parameterized, wildcard-escaped literal search. The studio read model returns 50 recent messages plus messages referenced by active drafts/approvals; older messages remain selectable through authenticated pagination. Immutable revisions remain authoritative.

Twitch notification application and envelope identity commit in one transaction. The ledger prunes to 10,000 entries on the first accepted notification after startup and every 100 thereafter, bounding the pruning overrun across restarts. Original source-message deduplication and moderation time fences remain independent/durable after envelope eviction. Private message metadata preserves allowlisted fragments and separate local wall/monotonic/session arrival fields; legacy event timestamp semantics stay unchanged. These fields do not calibrate broadcast latency. Protocol reference: [Twitch WebSocket handling](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/) and [chat event fields](https://dev.twitch.tv/docs/eventsub/eventsub-reference/#channel-chat-message-event).

Original source ASR and suggestion snapshots are separate from editable caption revisions. Exact source/range and SHA-256 executable/model fingerprints scope the transcription cache. Original-proposal assessments have append-only history and a separate private export. The local semantic adapter has a model-scoped bounded cache and serialized batch fills; disposal drops vectors/text. Context intervals are deterministic functions of validated source sentence timings, not generated speech.

Resource adapters read Linux process counters without command lines/environments and hash PID/start identities, so restarted/reused PIDs do not enter the same CPU delta. The local launcher supplies its reader PID. Allocated managed-disk scans deduplicate inodes, omit symlink targets, cache for five seconds and expose partial traversal. RSS sums double-count shared pages; short-lived work and between-sample peaks remain outside evidence. Linux counter interpretation follows [the proc stat manual](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html). Actual OBS/device and human acceptance remains separate.


Focused review panels stay mounted while hidden so local incomplete caption input and revision-bound notes survive panel switching. Older-message correction uses paged creator-only queries and refreshes the selected original until it enters the saved draft projection. State-load generations reject late responses/errors after newer saves or reads. A removed/unavailable selected ID remains explicit in the native selector instead of falling back to another option.

Plain-text WebVTT serialization is shared by draft preview, creator/managed/static reader captions and portrait subtitle generation. It escapes character references rather than dropping code operators or interpreting caption words as styling, following [WebVTT cue-text syntax](https://www.w3.org/TR/webvtt1/#webvtt-cue-text). Private preview cues translate relative reply time to original-source time, live in browser blob URLs and are revoked on replacement/unmount. They have no publication authority. Previously generated portrait files require explicit regeneration to use corrected serialization.
